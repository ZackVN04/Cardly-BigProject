🚀 Pipeline Overview

Cardly is designed around a 7-stage processing pipeline for business cards. Frontside and optional backside uploads are enqueued as background jobs run by background worker task queues, allowing real-time polling until the review stage.

🔌 REST API Specification

POST /api/v1/auth/register Create a new user account.

Request Payload Schema:

{ "email": "user@example.com", "password": "Password123!", "full_name": "Nguyen Van A" }

Response (201 Created):

{ "message": "User registered successfully" }
POST /api/v1/auth/login Issue access_token + refresh_token (Lockout after 5 failed attempts).

Request Payload Schema:

{ "email": "user@example.com", "password": "Password123!" }

Response (200 OK):

{ "access_token": "eyJhbGciOiJIUzI1NiIsIn...", "refresh_token": "eyJhbGciOiJIUzI1NiIsIn...", "token_type": "bearer" }
POST /api/v1/auth/refresh Rotate refresh token, issue new access token.

Request Payload Schema:

{ "refresh_token": "eyJhbGciOiJIUzI1NiIsIn..." }

Response (200 OK):

{ "access_token": "eyJhbGciOiJIUzI1NiIsIn...", "refresh_token": "eyJhbGciOiJIUzI1NiIsIn...", "token_type": "bearer" }
POST /api/v1/auth/logout 🔒 Revoke current refresh token.

Request Headers: Requires Bearer access_token.

Response (200 OK):

{ "message": "Logged out successfully" }
GET /api/v1/auth/me 🔒 Return current authenticated user.

Request Headers: Requires Bearer access_token.

Response (200 OK):

{ "id": "USR-123456", "email": "user@example.com", "full_name": "Nguyen Van A", "role": "user", "is_active": true }
POST /api/v1/auth/forgot-password Send 6-digit OTP to user email (valid for 5 minutes).

Request Payload Schema:

{ "email": "user@example.com" }

Response (200 OK):

{ "message": "OTP sent successfully" }
POST /api/v1/auth/verify-otp Verify 6-digit OTP code.

Request Payload Schema:

{ "email": "user@example.com", "otp_code": "123456" }

Response (200 OK):

{ "reset_token": "temp_verified_token" }
POST /api/v1/auth/reset-password Set new password with verified OTP token.

Request Payload Schema:

{ "reset_token": "temp_verified_token", "new_password": "NewSecurePassword123!" }

Response (200 OK):

{ "message": "Password reset successfully" }
POST /api/v1/documents 🔒 Upload image(s) + trigger pipeline (async). Supports two-sided uploads. Returns processing_id.

Request Body (multipart/form-data):

  • file: JPG / PNG / WEBP / PDF, max 10 MB (front side).
  • back_file: (Optional) JPG / PNG / WEBP / PDF, max 10 MB (back side, for two-sided cards).

Response (202 Accepted):

{ "processing_id": "PRC-20260521-7H3K9F", "status": "received", "uploaded_at": "2026-05-21T10:14:22Z" }
GET /api/v1/documents 🔒 List the current user's documents (paginated, filter by status).

Query Parameters: status (optional, filter), page (default 1), page_size (default 20)

Response (200 OK):

{ "items": [ { "processing_id": "PRC-20260521-7H3K9F", "doc_type": "business_card", "status": "ready_for_review", "uploaded_at": "2026-05-21T10:14:22Z" } ], "page": 1, "page_size": 20, "total": 1 }

Query Parameters: side (front / back, default front)

Response: Streams original binary data (with appropriate MIME headers e.g., image/jpeg or image/png).

POST /api/v1/documents/{processing_id}/reprocess 🔒 Re-run the pipeline (e.g. after a transient failure).

Response (202 Accepted):

{ "processing_id": "PRC-20260521-7H3K9F", "status": "processing", "reprocessed_at": "2026-05-26T12:00:00Z" }
DELETE /api/v1/documents/{processing_id} 🔒 Soft-delete the document (allowed only before confirmed).

Response (200 OK):

{ "message": "Document deleted successfully" }
PATCH /api/v1/documents/{processing_id}/review 🔒 Edit fields or update smart tagging context. Edits are logged for audit.

Request Body Payload:

⏱️ Timeline & Critical Sync

⚠️

Critical Sync Point: Contract Validation

During Week 1, interface contracts must be finalized and locked using test assets in the mock_data/ repository directory. This avoids late-stage redesign risks for P4, P5, and P6 mapping logic.

Week 1

Foundation & Mock Design

Establish core models in src/database.py and base settings config class in src/config.py. Setup baseline schemas.
Week 2

Stage Specific Implementations

Development on separate packages in parallel. Modules are tested locally using mock payloads.
Week 3

Background Orchestration

Integrate background workers using Redis and ARQ to loop stages sequentially. Run end-to-end processing trials.
Week 4

Security (P1) & Performance Tuning

Apply security dependencies to all routes. Verify password strength algorithms and lockout mechanisms. Prepare the production bundle.
